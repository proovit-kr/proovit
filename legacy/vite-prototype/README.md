# PROOVIT (프루빗) — AI 빌드 시즌제 리그 프론트엔드

`design-reference/`의 클로드 디자인 시안(.dc.html)을 실행 가능한 **React + TypeScript + Vite** 프로젝트로 재구성한 결과물이에요.
백엔드가 없으므로 모든 데이터는 목데이터이고, 화면·상태 전환은 우측 하단 **개발 툴바**로 전부 시연할 수 있어요.

---

## 실행 방법

```bash
npm install
npm run dev        # http://localhost:5173
```

| 스크립트 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 (기본 5173 포트, 자동으로 브라우저 열림) |
| `npm run build` | 타입체크(`tsc --noEmit`) 후 프로덕션 빌드 |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run typecheck` | 타입체크만 실행 |

## 개발 툴바 사용법

우측 하단의 초록색 **`DEV ✓ …`** 버튼을 누르면 패널이 열려요. 백엔드 없이 모든 화면과 가드를 시연하기 위한 도구예요.

| 그룹 | 옵션 | 효과 |
| --- | --- | --- |
| **역할** | 비로그인 | 보호 라우트 접근 시 `/signin?redirect=…`로 이동 |
| | 참가자(팀 없음) | `/apply` 접근 가능, `/dashboard`도 열림 |
| | 참가자(팀 있음) | `/apply` 접근 시 `/dashboard`로 리다이렉트 |
| | 운영자 | `/admin/*` 접근 가능. 참가자 화면 진입 시 `/admin/judging`으로 이동 |
| **시즌 상태** | 모집 전 / 모집 중 / 진행 중 | 랜딩·내비 CTA가 각각 **사전 신청 폼 / `/apply` / 리더보드**로 분기 |
| **스테이지** | S1 ~ 최종 심사 | 시즌 배너, 스테이지 진행 바, 제출 폼 잠금 상태가 일괄 갱신 |
| **1차 심사 통과** | 통과 / 미통과 | S2·S3 제출 잠금 해제, 대시보드 "Ch.4 잠김" 카드 노출 여부 |
| **바로가기** | 전체 라우트 링크 | 각 화면으로 즉시 이동 |

- 역할·시즌 상태·1차 심사 통과 여부는 `localStorage`(키: `proovit-dev-state`)에 저장돼서 **새로고침·딥링크에도 유지**돼요.
- 그 외 목데이터(제출물, 심사 결과, 크레딧 발급 등)는 메모리 상태라 새로고침하면 초기값으로 돌아가요.
- 로그인 폼은 목 인증이라 아무 값이나 통과해요. `ops`로 시작하는 이메일(`ops@proovit.kr`)은 **운영자**로 로그인돼요.

## 라우트

| 경로 | 화면 | 접근 |
| --- | --- | --- |
| `/` | 랜딩 (히어로·라이브보드·티커·비교·작동 방식·혜택·심사 기준·FAQ) | 공개 |
| `/leaderboard` | 시즌 리더보드 (상위 3팀 카드 + 전체 순위 + 티커) | 공개 |
| `/projects/:id` | 참가작 상세 (지표·뱃지·시즌 여정) | 공개 |
| `/seasons` | 시즌 아카이브 | 공개 |
| `/signin`, `/signup` | 로그인 / 회원가입 | 공개 |
| `/apply` | 참가 신청 (동의 3종 체크 전 제출 비활성) | 로그인 + 팀 없음 |
| `/dashboard` | 참가자 대시보드 (진행하기·제출 현황·혜택·상호 테스터 4탭) | 로그인 |
| `/dashboard/submissions/:stage` | 스테이지 제출 폼 (`S1`/`S2`/`S3`) | 로그인 |
| `/admin/judging` | 심사 콘솔 | ADMIN |
| `/admin/metrics` | 지표 검증 | ADMIN |
| `/admin/seasons` | 시즌 관리 | ADMIN |

### 이동·가드 규칙

- 비로그인 → 보호 라우트: `/signin?redirect=원래주소` → 로그인 성공 시 원래 주소로 복귀
- 참가팀 보유 상태에서 `/apply`: `/dashboard`로 리다이렉트
- 일반 유저가 `/admin/*`: `/`로 리다이렉트 (비로그인이면 로그인 화면으로)
- 운영자가 `/dashboard`·`/apply`: `/admin/judging`으로 리다이렉트
- 없는 경로: `/`로 리다이렉트

## 구조

```
src/
├─ api/            ProovitApi 인터페이스 + 목 구현 (백엔드 교체 지점)
│  ├─ types.ts     계약(시그니처)만 정의
│  ├─ mock.ts      메모리 DB 기반 목 구현
│  └─ index.ts     export const api: ProovitApi = mockApi
├─ components/     NavBar/OpsNavBar, SeasonBanner(실시간 D-day), StageProgress,
│                  Tabs, LeaderboardTable, Ticker, StatCounter, Badge, Button,
│                  Modal, Accordion, Sparkline, Toast, DevToolbar, RouteGuards
├─ hooks/          useCountdown, useCountUp, useLiveScores, useInView, useReducedMotion
├─ mocks/          전 페이지가 공유하는 목데이터 (시즌·팀·제출·지표·크레딧·심사)
├─ pages/          라우트별 페이지 + 각 페이지의 CSS Module
├─ store/          zustand 전역 상태 (인증 + 개발 툴바 + 도메인 액션)
├─ styles/         tokens.css (디자인 토큰), global.css (리셋·유틸·키프레임)
├─ types/          Season, Entry, StageSubmission, WeeklyMetric, CreditOffer,
│                  CreditClaim, PeerReview 등 도메인 타입
└─ utils/          format(숫자·전환율), stage(스테이지 파생 로직)
```

### 스타일 방식

시안이 Tailwind가 아니라 **인라인 style 문자열** 기반이라 **CSS Modules**로 옮기고, 색·폰트·라운드·간격·그림자는 전부
`src/styles/tokens.css`의 CSS 변수로 중앙화했어요.

- 배경 딥 네이비 `--c-bg: #0B1220`, 포인트 라임 `--c-lime: #C8FF3D` (다크 테마 고정)
- 한글 Pretendard(`--font-sans`), 숫자·지표 JetBrains Mono(`--font-mono`)
- 운영자 콘솔은 별도 배경 토큰(`--c-bg-ops`, `--c-surface-ops`) 사용

### 백엔드 연결 방법

`src/api/types.ts`의 `ProovitApi`를 구현한 HTTP 클라이언트를 만들고 `src/api/index.ts` 한 줄만 바꾸면 돼요.

```ts
export const api: ProovitApi = httpApi; // mockApi 대신
```

페이지는 `api`를 직접 부르지 않고 zustand 스토어(`useAppStore`)를 거치므로, 화면 코드는 그대로 둬도 돼요.

## 구현된 인터랙션

- **실시간 D-day 카운트다운** (일 + 시:분:초): 랜딩 킥오프, 참가 신청 마감, 제출 마감
- **리더보드 카운트업 + 스파크라인 드로우 + 실시간 점수 증가**(위 순위를 넘지 않도록 증가폭 제한)
- **전광판 티커** 무한 흐름, 호버 시 정지
- **대시보드 4탭** 실제 전환, "혜택 탭 →" 같은 탭 간 이동
- **제출 폼 전환율 실시간 자동 계산** (방문자·신청자 입력 즉시)
- **크레딧 발급 코드 복사 모달** (`PROOVIT-S1-DAWN`, 복사 후 라벨 전환)
- **심사 콘솔 통과 확인 모달**, 보류 + 피드백 입력, AI 리포트 아코디언
- **지표 검증**: 확정 처리, 원본 요청 툴팁, 증빙 원본 확대 오버레이
- **FAQ 아코디언**, 스크롤에 따라 채워지는 "작동 방식" 트랙, 섹션 페이드인
- **참가 신청 동의 3종** 체크 전 제출 버튼 비활성
- `prefers-reduced-motion: reduce`면 카운트업·라이브 갱신·선 드로우 애니메이션을 끄고 즉시 최종 상태로 표시
- 모바일에서 히어로·비교 섹션 세로 스택, 표는 가로 스크롤

## 목데이터 기준값

시안의 숫자를 그대로 사용해 리더보드·참가작·대시보드·심사 콘솔이 서로 아귀가 맞아요.

| 순위 | 서비스 · 팀 | 유효 가입자 | 주간 증가 | 상태 |
| --- | --- | --- | --- | --- |
| 1 | 빵집레이더 · 새벽로켓 | 412 | +38% | 매출 발생 · 검증됨 |
| 2 | 링크줍줍 · 북마클릿 | 356 | +9% | 매출 발생 · 검증됨 |
| 3 | 회의록요정 · 미닛테이커 | 298 | +7% | 검증됨 |
| 4 | 텃밭일지 · 초록손 | 241 | +12% | 검증됨 |
| 5 | 산책메이트 · 강아지먼저 | 187 | -4% | 검토 중 |
| 6~8 | 레시피환산기 152 · 중고가늠 118 · 모임비 정산 87 | | | |

그 외: 총 상금 ₩3,000,000 · 모집 20~40팀 · 사전 신청 128명 · 참가 27팀/생존 19팀 ·
심사 대기 12건 · 이번 주 지표 제출 18건(확정 11 / 대기 7) · S1 전환율 12.4%(492명 방문, 61명 신청)

## 시안과 다르게 구현했거나 생략한 부분

1. **빵집레이더 주간 증가율**: 시안이 리더보드에선 `+18%`, 참가작 상세에선 `+38%`로 서로 달랐어요. 요청대로 **+38%로 통일**했어요.
2. **랜딩 v1**은 v2의 부분집합이라 **v2 기준으로만** 구현했어요.
3. **라이브보드 순위 역전(swap) 애니메이션 생략**: 시안엔 3위가 2위를 추월하며 행이 자리를 바꾸는 연출이 있었는데, 점수 롤업·실시간 증가만 구현하고 순서는 항상 유효하게 유지했어요.
4. **`/seasons`는 시안이 없어** 토큰·공용 컴포넌트로 새로 구성했고, 아카이브를 채우려고 **시즌 0(파일럿) 목데이터**를 추가했어요.
5. **Auth 시안은 한 화면 탭 전환**이었지만 라우트 요구사항에 맞춰 **`/signin`·`/signup` 두 라우트로 분리**하고, 세그먼트 탭으로 서로 이동하게 했어요.
6. **Submit 시안은 S1 전용**이라 `/dashboard/submissions/:stage`로 **일반화**했어요. S2·S3는 같은 폼을 쓰고, 잠긴 스테이지엔 안내 문구를 보여줘요.
7. **제출/혜택 잠금 규칙을 파생값으로 변경**: 시안은 잠금 상태가 고정 마크업이었는데, 여기서는 현재 스테이지와 1차 심사 통과 여부로 계산해요(`utils/stage.ts`).
8. **심사 콘솔 "보류 + 피드백"**: 시안은 textarea 토글까지였는데, 입력 후 한 번 더 누르면 실제로 **보류 처리**까지 되게 연결했어요.
9. **증빙 이미지**: GA4 스크린샷 원본이 없어 시안과 동일하게 **플레이스홀더 박스**로 뒀어요(클릭 시 확대 오버레이만 동작).
10. **모바일 히어로**: 시안의 `auto-fit minmax(340px)` 그대로면 375px 화면에서 라이브보드가 가로로 잘려요. **760px 이하에서 1열 강제**로 바꿨어요.
11. **더미 링크**: 시즌 규칙 / 유효 이용자 기준 / 스폰서 문의 / SNS / "가이드 열기"는 시안과 마찬가지로 **앵커 플레이스홀더**예요.
12. **개발 툴바의 역할이 4종**: 요청은 3종(비로그인/참가자/운영자)이었지만, `/apply` 가드를 시연하려면 팀 유무 구분이 필요해 **참가자(팀 없음)** 을 추가했어요.
13. **상태 저장 범위**: 로그인·툴바 상태만 `localStorage`에 저장하고, 제출·심사 결과 등 도메인 목데이터는 메모리라 새로고침하면 초기화돼요.
14. **티커 톤 통일**: "매출 발생"이 랜딩 시안에선 라임, 리더보드 시안에선 골드였는데 **골드로 통일**했어요.
15. **상호 테스터 "피드백 작성하기"** 버튼은 아직 **모달·폼이 없어 동작하지 않아요**(시안에도 후속 화면이 없었어요).
16. **랜딩 이메일 사전 신청**은 목 API를 호출하고 토스트·체크 애니메이션만 보여줘요(저장소 없음).
